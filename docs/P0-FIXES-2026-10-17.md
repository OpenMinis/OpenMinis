## 1. 保存链路（SAVE-1/2/3/4）

### 新的不变量

1. **未知长度 ≠ 成功。** `FileSaveGuard` 返回三态 `INTACT / EMPTY / UNKNOWN`；`UNKNOWN` 必须由调用方用内容回读探针升级，不能直接当成功。
2. **只有一个复制实现。** 所有用户可见保存都走 `io/VerifiedCopy.kt`：SAF 文档、MediaStore、pre-Q 普通文件、崩溃 zip、图片 Bitmap。
3. **MediaStore 先 pending 再验证。** 行插入时 `IS_PENDING=1`；只有 `VERIFIED` 才清 0；`FAILED/UNVERIFIED` 删除该行。任何空媒体项都不会出现在相册/Downloads。原始字节复制（相册文件、崩溃 zip）按源长度精确校验；Bitmap 渲染没有源长度，按"非空 + 回读探针"校验。
4. **`Bitmap.compress` 的返回值是硬条件。** 返回 false 直接失败，不再忽略。
5. **pre-Q 原子写。** `.name.uuid.part` → 校验长度 → rename；失败删除 sidecar，目标不出现半截文件。
6. **崩溃 zip 的 SAF 路径也验证。** `MainActivity` 的选择器回调改为 `VerifiedCopy.copyFileToDocument`，验证失败不打开 ACTION_VIEW。

### 文件

| 文件 | 作用 |
|---|---|
| `io/FileSaveGuard.kt`（新） | 纯决策表，JVM 可测 |
| `io/VerifiedCopy.kt`（新） | copy + length/probe 验证 + MediaStore pending 生命周期 |
| `ui/sandbox/FileSaveActions.kt` | 统一 SAF / 相册文件 / Bitmap 三个入口 |
| `ui/components/FullscreenImageViewer.kt` | 删除本地 `saveToGallery`，解码失败也提示失败 |
| `ui/components/ImageGalleryViewer.kt` | 同上，复用共享实现 |
| `crash/CrashFrequencyDetector.kt` | Downloads 的 Q+/pre-Q 两条路径接验证 |
| `MainActivity.kt` | 崩溃 zip 的 SAF 回调接验证 |

### 测试

- `io/FileSaveGuardTest.kt`：10 条决策表用例，含 `UNKNOWN` 不得为成功、探针不能救回 `EMPTY`。
- `io/VerifiedCopyTest.kt`（Robolectric）：用 `FakeDocProvider` 模拟"`openAssetFileDescriptor` 返回 -1、内容可读"的 OEM provider；覆盖验证成功、空文档不成功、缺失文档失败、文件原子复制、writer 拒绝。

## 2. 滚动仲裁（SCROLL-1）

### 新的不变量

1. **每个命令带 generation。** `ChatScrollController` 在等待 Mutex 前捕获 generation，拿到锁后重新校验；手势/会话切换递增 generation，旧命令即使已在队列里也变成 no-op。
2. **手指按下即接管。** `DragInteraction.Start → beginUserGesture()`：取消队列并拒绝新的程序化滚动；`Stop/Cancel → endUserGesture()`。
3. **会话切换清空旧命令。** `SESSION-REENTRY` 效果先 `invalidate("session-switch")`，再 pin/滚动。
4. **一个宽限常量。** `USER_SCROLL_INTERRUPT_MS = 1_000L`，`SEND_FOLLOW_GRACE_MS` 直接引用它；原来 1 s/2 s 的裂缝消失。

### 文件

- `ui/chat/ChatScrollController.kt`：`ScrollTarget` 抽象（便于 JVM 测试）、generation、手势闸门。
- `ui/chat/ChatScreen.kt`：手势开始/结束、会话切换失效、常量统一。

### 测试

`ui/chat/ChatScrollControllerTest.kt` 新增：
- 手势前入队的命令在拿到锁后被丢弃；
- 手指按下期间所有命令被抑制；
- `invalidate` 丢弃旧 generation；
- 手势取消 previous-turn walk。

## 3. 流式块解析（ICU-1）

### 新的不变量

1. **live 片段增量解析。** `parseMarkdownBlocksIncremental(previous, text)` 复用 `previous` 中除最后一个 block 外的全部结果，只重解析最后一个 block 的起点之后的内容。
2. **只在安全时复用。** 新文本必须以旧文本为前缀，且最后一个 block 的 `raw` 必须是旧文本中的连续切片；否则整段重解析（宽松列表、片段替换、非追加编辑都走这条路）。
3. **段落扫描先看首字符。** `isParagraphTerminator` 只对 `# `、```` ``` ````、`>`、`-*_+`、`!`、数字开头才调 regex；普通散文行不再进入 ICU。
4. **段落循环必须前进。** `paraLines.isNotEmpty()` 保护：`#not-a-heading` 这种"看起来像块首、但没有匹配任何上层分支"的行必须被消费，否则外层死循环（本次测试暴露的既有缺陷）。
5. **可观测。** `BlockParseMetrics` 每 20 tick 输出 `fullChars/reparsedChars/savedPct`，真机上能直接确认增量是否生效。

### 文件

- `ui/chat/StreamingMarkdownIncremental.kt`（新）：snapshot、增量拼接、指标。
- `ui/chat/StreamingMarkdownParse.kt`：快路径 + 循环前进修复。
- `ui/chat/StreamingMarkdownBlockBody.kt`：live 分支改用增量，保留 prewarm/冻结缓存写入。

### 测试

`ui/chat/StreamingMarkdownIncrementalTest.kt`：
- 60 段追加只重解析尾部；
- 未闭合 fence 增长后结果与全量一致；
- 表格追加行只重建表格；
- 尾随空行不破坏后缀匹配；
- 非追加编辑 / 单 block 回退全量；
- 首字符快路径仍能识别 heading/fence/quote/list/numbered/image/table；
- `#not-a-heading` 不死循环。
