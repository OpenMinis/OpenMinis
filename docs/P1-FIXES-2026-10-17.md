## 1. 解析与渲染

### CRASH-5 未闭合 fence

- `MdBlock.CodeBlock` 增加 `closed: Boolean = true`；解析到输入末尾仍未闭合时置 false。
- 渲染层：`⚠ ` 前缀 + 警示色（不新增翻译键），并且 **禁用「▶ 运行」**——半截代码不能被执行。
- 测试：闭合/未闭合标志、增量解析保持标志。

### CRASH-7 等长替换显示旧内容

`FlatChatItem.AssistantMarkdownBlock` / `AssistantLegacyContent` 的 `equals` 改为内容比较：

- `rawText`、`segmentText`、legacy `content` 用完整 `String.equals`；
- `messageMarkdown` 仍只比长度——它是整条消息的拼接文本，只服务 Copy Markdown，是历史 profile #3 的热点，不能每 fragment 每 tick 全量比较。
- 测试：等长不同内容判不等、相同内容判相等、legacy 同型。

### CRASH-4 blockquote 深度

`parseMarkdownBlocks(content, depth)` 增加 `MAX_BLOCKQUOTE_DEPTH = 16`；到顶后内层内容降级为 `Paragraph`，不再递归。测试 40 层 `> ` 嵌套不溢出、层数 ≤ 17。

## 2. 流式传输

### PROV-1 共享 SSE 解析器

新增 `provider/SseEventParser.kt`：

- 事件以空行结束，多条 `data:` 用 `\n` 拼接（SSE 规范）；
- 保留 `event:` / `id:`；忽略注释与未知字段；容忍 CRLF 与 `data:{...}` 无空格；
- EOF 时 flush 最后一个事件（代理不写结尾空行时保留 finish_reason）。

OpenAI / Anthropic / Gemini 三家统一改为 `for (payload in ssePayloads(reader))`。`[DONE]` 保持原语义。测试：解析器 9 条 + Anthropic 多行事件端到端 1 条。

### PROV-2 TTFB watchdog

新增 `provider/StreamTtfb.kt`：120s 内拿不到响应头就 `call.cancel()`，并把 IOException 映射为可重试的 `LLMError.TransientError`。只约束"首字节前"，流式进行中不设总时长。

Anthropic / Gemini 接入，并补上取消链路：

- `Job.invokeOnCompletion { call.cancel() }`：collector 取消时能打断阻塞中的 `readLine`；
- `awaitClose { call.cancel(); response.close() }`：不再空实现。

测试：正常响应透传；`SocketPolicy.NO_RESPONSE` 在 150ms 档位被 watchdog 取消并映射为 TransientError。

## 3. 并发与生命周期

### CRASH-1 tracker 原子性

- `SessionActivityTracker`：`setActive` / `setInactive` / `setPresent` / `setAbsent` / `clearPresence` 加 `@Synchronized`，覆盖"边沿判断 + 集合更新"整体；集合写入改 `StateFlow.update {}`。
- `SubAgentActivityTracker`：所有 `_members.value = _members.value ...` 改为 `update {}`；移除 `mutate`/`appendLog` 里与 update 混用的 `synchronized`。`jobs` / `userStopped` 本就是并发容器。
- 测试：64 个 session 并发激活/注销后集合精确；32 个 sub-agent 并发 start/update/finish 后 roster 精确。

### CRASH-2 安全 Context

`ToolOverlayController` 构造改为可注入：

```kotlin
private val backgroundRepo: BackgroundSettingsRepository? =
    (context.applicationContext as? MinisApp)?.backgroundSettingsRepository
```

不再是裸 `as MinisApp`；null 时只是不持久化浮窗位置。其余 UI 侧的 `as MinisApp` 留在原位（Activity/Application Context 由 manifest 保证；`ChatViewModel` 的属性是懒加载、改动面大），本轮不扩大。

### H-3 FGS executor

`AgentForegroundService.onDestroy` 增加 `islandProbeExecutor.shutdownNow()`，与服务重建对称。

### H-5 sticky bus CAS

`OverlayComposeBus.consumeSticky` 改为 `AtomicReference` CAS 循环：并发消费只有一个 winner，不再双投递。测试：16 线程抢同一请求恰好 1 个成功、错误 session 不消费。

### CRASH-8 崩溃报告写入

新增 `CrashReportWriter`：

- 目录不可写 / 磁盘满 / provider 失败全部吞掉，绝不从 ACRA sender 抛出；
- 先写 `.tmp` + `flush` + `fd.sync()`，再 rename；
- 512 KB 上限，超出截断并标注；
- `filesDir/logs` 失败时回退 `cacheDir/logs`。

测试：正常写入、截断、不可写目录返回 null、失败不留临时文件/目标。
