## 2. TERM-1 PTY 就绪握手

`TerminalScreen` 不再 `delay(500)` 后盲发 `initCommand`：

```kotlin
val ready = withTimeoutOrNull(5_000L) {
    terminalSession.state.first { it == RUNNING || it == STOPPED }
}
if (ready == RUNNING) send(sanitizedInitCommand)
```

- 冷启动慢设备不再把预填文本丢给尚未读 stdin 的 shell；
- 5s 超时或 STOPPED 时放弃发送（避免写入死 PTY）；
- 继续保留控制字符过滤（CR/LF/ESC/NUL/DEL）。

## 4. MCPOAUTH-1 固定端口

`MCPOAuthController.authorize`：

- 用户未配置 redirect URI 时，`findFreeLoopbackPort(54546, span=20)` 先探测可用端口，
  用实际端口构造 `http://localhost:<port>/callback`；端口全忙则用 OS 分配的临时端口；
- 用户显式配置 redirect URI 时原样使用，但**必须带显式端口**（否则返回明确错误，
  不再静默绑定 54546 却把无端口 URI 发给 IdP）；
- `OAuthCallbackServer` 仍显式绑定 127.0.0.1；不再依赖固定 54546。

测试：`MCPOAuthPortTest` 覆盖"首选端口被占用→选下一个"和"空闲时原样返回"。

## 5. MCP-FT-1 流式 Base64

新增 `mcp/server/tools/FileTransferCodec.kt`：

- 按 256KB 分块读取；
- `Base64.getEncoder().wrap(OutputStream)` 保证 padding 只在最终 quantum，
  不会出现分块独立编码产生的中途 `=`（测试抓到的真实问题）；
- SHA-256 在同一次读取中增量计算；
- 不再 `file.readBytes()` + 一次性 `encodeToString`，去掉 8MB 字节数组峰值。

仍保留的限制：MCP 协议当前要求 `CallResult` 持有一个完整字符串，所以最终 base64
字符串（8MB 文件约 10.7MB）仍在内存；要彻底流式化需要改 HTTP 响应写出路径，留作后续。

测试：`FileTransferCodecTest` 用 300KB 分块与一次性解码/哈希对比，覆盖空文件。

## 6. CFG-1 确认门阻塞

三处一起改：

1. **ConfigBridge**
   - 新增顶层 `config/ConfigBridgeWrites.kt` 的 `writeFieldsSuspending(...)`；
   - `auditRevert` 改为 `suspend fun auditRevertSuspending(...)`；
   - 移除 offload 路径上的 `runBlocking`。
2. **ConfigOffloadHandler**
   - `handle` 保留同步壳（接口要求），内部 `handleInternal` 改为 `suspend`；
   - 新增 `override suspend fun handleAsync`，写路径调用 suspend 版本；
   - `catch` 先重新抛出 `CancellationException`，避免把取消吞成 INTERNAL 错误。
3. **NativeOffload**
   - `NativeOffloadHandler` 增加默认 `suspend fun handleAsync`（其它 handler 零改动）；
   - watchdog 在 handler 协程里 `withTimeout(handlerDeadline)`，超时会取消确认等待；
   - 外层 `poll(timeout + 2s)` 仍兜底"不响应取消"的同步 handler；
   - 超时结果提取为 `handlerTimeoutResult`，避免重复构造。
4. **ConfigConfirmationGate**
   - `suspendCoroutine` → `suspendCancellableCoroutine`；
   - 取消时 `cancel(id)` 清理 awaiter/timeout/queue/前台 pending，并推进下一条；
   - `resolve` 只 resume 仍 active 的 continuation。
5. **ConfigAuditScreen** 改用 `auditRevertSuspending`，去掉 UI 层的嵌套 `runBlocking`。

测试：`ConfigConfirmationGateNotifyTest` 新增"取消调用方后 pending 被清空"用例。
