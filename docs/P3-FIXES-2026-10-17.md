## 1. SEC-1 NativeOffload peer 认证

`NativeOffload.handleClient` 在读 magic/version 之前校验 peer：

```kotlin
val peerUid = client.peerCredentials.uid
if (peerUid != Process.myUid()) return
```

- proot guest 以本应用 UID 运行，所以正常调用不受影响；
- 抽象 socket 没有文件权限位，peer UID 是唯一可靠的内核边界；
- `getPeerCredentials()` 失败时 fail closed（拒绝并记日志），不退回"无认证"；
- 无需改 native 协议、无需 token、无需改 `deps/proot`。

风险边界：同 UID 的进程（本应用自己的其他进程）仍可连接，这是设计预期；跨 UID 的 App 被拒绝。

## 2. SEC-5 Rhino ClassShutter

`ExecuteCodeTool` 在 `enterContext()` 之后、`initStandardObjects()` 之前设置：

```kotlin
cx.setClassShutter(object : ClassShutter {
    override fun visibleToScripts(fullClassName: String) = false
})
```

- `java.*`、`Packages.*`、`Class.forName` 等 Java interop 对脚本不可见；
- 只保留 `print` / `console` / `__minis_call` 三个宿主桥；
- `execute_code` 的文档语义（JS-only sandbox）现在与实现一致；
- 指令预算（`INSTRUCTION_BUDGET`）与内存/输出上限保持不变。

测试：`ExecuteCodeToolTest` 覆盖正常 JS、`java.lang.Runtime`、`Packages.java.io.File`、`Class.forName` 四种输入。

## 3. S-14 命令/参数日志脱敏

新增 `util/LogRedaction.kt`：

```
cmd=<program> len=<n> sha=<sha256 前 12 位>
```

- 首 token 形如 `SECRET=value` 时记 `cmd=<env>`，避免把环境赋值当程序名泄露；
- 同样的命令得到同样摘要，可关联重复执行；不泄露原文。

接入点：

| 位置 | 改动 |
|---|---|
| `ShellExecutor` | `Executing` / timeout / failed 三处不再打印完整 `command` |
| `ExecutionCoordinator` | `[diag] execute` 改用 `LogRedaction.command()` |
| `NativeOffload` | 正常接收日志删除 `argv`，只留 `name/argc/envc`；watchdog 超时日志改用 `argc` |
| `PRootKernel.updateProxy` | 不再打印 `http_proxy` URL（未来若加 token，不会进日志） |

测试：`LogRedactionTest` 覆盖 Bearer/URL 凭据、`MYSQL_PWD=` 首 token、确定性、空命令。

仍然可能出现在日志里的内容：其他模块自行打印的 tool args / HTTP body 不在 S-14 的这四个调用点范围内。

## 4. SEC-3 SecurityGate 规则匹配

新增 `security/RulePattern.kt`，替换 `SecurityGateImpl` 里"每次调用 compile 两个 Regex"的实现：

- allow 规则：线性 glob（`*` / `?`）做 **whole-unit prefix** 匹配；
- deny 规则：线性 glob 全串匹配 + 历史 `contains(trim('*'))` 兜底；
- 没有正则引擎、没有回溯爆炸、每次调用零 `Pattern.compile`；
- 上限：pattern 512 字符、target 8,192 字符；
- deny 在 target 超限时 **fail closed**（返回匹配），allow 在超限时拒绝；
- allow 的 `git` 仍只覆盖 `git status`，不会覆盖 `grep category`；`/tmp/*` 仍覆盖 `/tmp/a`。

测试：`RulePatternTest` 覆盖 allow 前缀语义、`?`、deny 全串/字面量、16K 星号模式、超长 target fail-closed。

行为差异：旧实现的 `.*` 不跨换行，新 glob 的 `*` 会跨换行；命令里出现换行时 deny 更容易命中（安全方向，不会漏放）。

## 6. 设备/后续

- `LocalSocket.getPeerCredentials()` 在 minSdk 26 上可用；建议在 API 26 与 API 34 各跑一次 native_offload 调用确认。
- `SEC-2` 若不引入 token/userinfo，同设备 App 仍可把 17890 当代理（仅限用户开启 `log`/`cut` 时）；`SEC-4` 的 CORS `*` 仍在，但生产 token 总是生成，浏览器无 token 拿不到结果。
- `SEC-3` 的 deny fail-closed 会让任何超过 8K 的命令在存在 deny 规则时被拒绝；如产品不接受，可改为"先截断匹配 + 超长单独审计"，但那会重新引入绕过面。
