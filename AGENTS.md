# AGENTS.md

This file provides context and instructions for AI coding agents working in the OpenMinis repository.

---

## Repository overview

OpenMinis ("Minis") is a native mobile AI agent app for iOS and Android. It connects to leading model providers (Claude, GPT, Gemini, and others) and gives those models a real on-device Linux sandbox to work with, along with browser automation, device integrations, extensible skills, and persistent memory.

**This repository is a mirror of a private development tree. It does not accept pull requests.** Bugs, feature requests, and discussion belong in [GitHub Issues](https://github.com/OpenMinis/OpenMinis/issues).

---

## Repository layout

```
src/ios/          iOS app (Swift / SwiftUI) + share, widget and file-provider extensions
src/android/      Android app (Kotlin / Jetpack Compose) + JNI native code
src/shared/       Assets shared by both platforms
deps/             Native dependency build scripts and vendored sources (iSH, PRoot submodules)
docs/specs/       Architecture and interface specifications
scripts/          Rootfs preparation and developer tooling
.github/          CI workflows and issue templates
```

Key subdirectories inside `src/ios/`:

| Directory | Purpose |
|---|---|
| `Agent/` | Core agent runtime — chat, shell, browser, background, session, sync, speech |
| `Providers/` | Model provider integrations |
| `NativeOffloads/` | Heavy or platform-specific work handed off to native code |
| `Views/` | SwiftUI screens |
| `iSH/` | Bridging layer to the iSH sandbox |
| `WebApp/` | In-app browser / web runner |
| `ShareExtension/` | iOS Share Sheet extension |

Key subdirectories inside `src/android/app/src/main/`:

| Directory | Purpose |
|---|---|
| `java/…/` | Kotlin app code (Compose UI, agent runtime, provider integrations) |
| `cpp/` | JNI libraries: `pty_bridge`, crash handler, `jieba_jni` (built by CMake via Gradle) |
| `assets/` | Sandbox binaries and Alpine rootfs (generated; gitignored) |
| `jniLibs/` | Pre-built `.so` files (generated; gitignored) |

## Building

Native dependencies (iSH on iOS, PRoot on Android, FFmpeg, LAME) are **built from source**; they are not committed as binaries. See [BUILDING.md](BUILDING.md) for the full guide and troubleshooting. The short version is below.

### Common prerequisites

Clone with submodules — the iSH and PRoot forks are submodules:

```sh
git clone --recurse-submodules https://github.com/OpenMinis/OpenMinis.git
# Or, if already cloned:
git submodule update --init --recursive
```

Copy the build-time customization templates before building:

```sh
cp src/ios/Configs/ProviderCustomization.xcconfig.example \
   src/ios/Configs/ProviderCustomization.xcconfig

cp src/android/app/provider-customization.properties.example \
   src/android/app/provider-customization.properties
```

Leaving the values empty is fine — the app compiles and runs. Missing values cause the specific feature that needs them to fail at runtime.

### iOS

**Requirements:** macOS (Apple Silicon recommended), Xcode with iOS SDK (targets iOS 26.2, Swift 6.0), Homebrew packages `ninja llvm libarchive pkg-config`, Python 3 + `meson`.

```sh
# Run from repository root, in this order (FFmpeg links against LAME)
./deps/build_lame.sh
./deps/build_ffmpeg.sh
./deps/build_ish.sh
./deps/prepare_alpine_rootfs.sh

open src/ios/Minis.xcodeproj   # then build the Minis scheme
```

Command-line build:

```sh
xcodebuild -project src/ios/Minis.xcodeproj -scheme Minis \
           -configuration Debug -destination 'generic/platform=iOS' \
           CODE_SIGNING_ALLOWED=NO build
```

Run unit tests:

```sh
xcodebuild test -project src/ios/Minis.xcodeproj -scheme MinisTests \
                -destination 'platform=iOS Simulator,name=iPhone 16'
```

### Android

**Requirements:** JDK 17, Android SDK (compileSdk 36, minSdk 26), Android NDK r28+ (`$ANDROID_NDK_HOME`), CMake 3.22.1.  
Gradle comes from the wrapper (Gradle 8.11.1, AGP 8.7.3, Kotlin 2.1.0) — do not install separately.

```sh
./deps/build_proot.sh
./scripts/prepare_android_sandbox.sh

cd src/android
./gradlew :app:assembleDebug          # → app/build/outputs/apk/debug/
./gradlew :app:installDebug           # install onto a connected device
```

Run tests:

```sh
./gradlew :app:testDebugUnitTest        # JVM unit tests
./gradlew :app:connectedAndroidTest     # instrumented; needs a device or emulator
```

## Key architectural notes

- **Sandbox:** The Linux environment is iSH (iOS) or PRoot + Alpine (Android). Both run entirely on-device. Sandbox assets (`assets/`, `jniLibs/`) are generated by build scripts and gitignored — never commit them.
- **FFmpeg must stay LGPL:** Do not add `--enable-gpl` or `--enable-nonfree` when building FFmpeg. See [THIRD_PARTY_LICENSES.md](THIRD_PARTY_LICENSES.md).
- **Only arm64:** The Android build targets `arm64-v8a` only (`abiFilters`). Use an arm64 device or emulator image.
- **Swift 6 / strict concurrency:** iOS code is compiled under Swift 6; pay attention to actor isolation and sendability when modifying agent runtime code.
- **Specs:** `docs/specs/` contains architecture and interface specifications (debug server API, iSH sandbox summary, Minis URL scheme). Read the relevant spec before modifying the corresponding subsystem.

## What agents should and should not do

**Do:**
- Follow the build order in BUILDING.md when touching native dependencies.
- Run the existing test suites (`MinisTests`/`MinisUITests` on iOS; Gradle unit/instrumented tests on Android) after code changes.
- Keep FFmpeg on its LGPL configuration.
- Preserve vendored `LICENSE` files in `deps/`.
- Check `docs/specs/` before modifying the sandbox bridge, URL scheme, or debug server.

**Do not:**
- Commit generated sandbox artifacts (`assets/alpine-minirootfs.tar.gz`, `assets/proot-aarch64`, `jniLibs/`).
- Open pull requests — this is a mirror and PRs cannot be merged.
- Add `--enable-gpl` or `--enable-nonfree` to the FFmpeg build.
- Change `abiFilters` to include x86 or x86_64 without also updating all native build scripts.

## CI

The **Build iOS IPA** workflow (`.github/workflows/build-ios-ipa.yml`) is the supported way to produce an iOS `.ipa` from a non-macOS machine. It builds all native dependencies and archives the app. Trigger it manually:

```sh
gh workflow run "Build iOS IPA" --ref main
gh run watch
gh run download <run-id> -n ios-ipa
```

Without signing secrets the workflow produces an unsigned IPA (useful for verifying the build). See BUILDING.md for the required repository secrets to produce a signed IPA.
